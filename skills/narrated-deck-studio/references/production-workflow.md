# Production workflow

## 1. Establish the brief and evidence

Reuse conversation answers. Save the intended audience, decision, formats, budget, tone, voice permission, caption/disclosure choices and delivery destination privately. Inventory competing scripts/decks before choosing source priority. For product footage, name the environment and permitted data. An account that lists a project may still lack its files; a tiny fixture catalogue cannot answer a live search-coverage question.

Keep operational investigation separate from presentation production. Reproduce a suspected limitation through authorised reads; do not change hosted permissions, catalogue contents or product behavior merely to make the film look successful. Use public documents or clearly labelled prepared demo data when restricted footage is not authorised.

## 2. Design and rehearse the story

Write a compact beat sheet before prose: actor, starting question, action, visible result, why it matters, next step. Carry one plausible example through search, inspection, comparison and outcome where appropriate. Do not invent an admin preview button, a completed upload, or universal access because it would simplify the story.

Rehearse the real UI first. Confirm the query, result count, document, matching page, navigation controls and final state. Exercise the hardest transfer or recovery action with realistic data before recording. A tiny upload may finish before pause can be shown. Use an authentic representative file or a clearly identified local simulation; never present fabricated progress as actual product behavior.

For decks, use one narrative job per slide, a claim-led title and a visible source. Alternate overview, evidence and conclusion where the argument calls for it. Preserve editable source structure when revising an existing deck.

## 3. Build a representative section

Produce one demanding section early: a dense slide, document search/preview, or multi-step interaction. Check it at delivery size. This is a rehearsal candidate, not a release approval. Use it to settle typography, safe framing, voice pronunciation and pace before generating a whole film.

For a general or first-time audience, 135–150 spoken words per minute is a useful starting range. Use complexity and actual comprehension to choose pacing. Reserve a settled visual lead-in and reading time after speech; 0.8–1.5 seconds before a simple explanation and 2–4 seconds after a result are starting points, not mandatory numbers. Complex diagrams need longer. If the duration budget cannot accommodate readable evidence, shorten the script or reduce scope before recording.

## 4. Produce narration and capture

Use an already accepted voice only within its recorded permission. Follow the managed pipeline's take-selection requirements when using it; do not impose repeated full auditions on an independently produced revision with an unchanged accepted voice unless quality or the user requires them.

Prepare short spoken sentences and pronunciations for names, abbreviations and numbers. Candidate speech can be generated in passages. Review generated content with independent ASR and signal analysis: omissions, repeated phrases, wrong numbers, names, clipping and internal dropouts. ASR variants alone do not prove an audio defect; investigate material ambiguity. A voice-identity claim requires appropriate listening evidence.

After candidate repairs, construct and select one continuous master including intentional lead-ins and reading holds. Store its checksum. Do not insert time, splice or stretch this selected master during visual editing. If pacing still needs new silence or a rewritten sentence, make a new version and repeat the affected audio, timeline and approval checks.

Capture actual interactions, not isolated screenshots pretending to be a flow. Assert the observed UI state before each narrated beat. Record console/page errors where tools allow. Save source capture hashes and action/cue timestamps. Prefer meaningful interactions near normal speed; omit dead loading time only when the edit remains understandable. Do not use a global video speed adjustment to conceal timing errors.

## 5. Measure, compose and frame

Map each paragraph to the exact frame range that supports it. Prefer state markers in capture plus measured frame timestamps for interactive films; use forced alignment for an existing continuous recording. Neither word-count estimates nor ASR alone establishes which screen was visible. Review ambiguous alignment semantically.

Make the relevant result visible before referring to it. Keep result counts, query terms, page numbers, comparison labels, pause/resume controls and draft/publication state inside the final crop. Open actual PDFs, show the relevant matching page and enlarge the figure when the narration discusses it. A filename listing is not a document preview.

Recordly or another editor is optional. Use it when it improves cursor/zoom framing. Keep a cache key containing source hash, trim interval, project/settings hash and tool version. An old export success receipt is invalid after a source or crop change. Inspect the final exported zoom, including the first and last frames of critical motion; source coordinates do not prove the final crop.

Use the exact selected master from time zero. Keep captions aligned to it if requested; verify absence of embedded subtitles if that was requested. Burned-in text requires visual inspection and cannot be detected by counting subtitle tracks. Separate chapter titles from subtitle narration.

## 6. Verify and deliver

Use the QA contract and helper. Inspect every narrated state in the final film, with dense documents and consequential outcomes at full size. Also sample action/transition boundaries; a midpoint frame does not prove the whole motion. Review speech content and signal checks separately. Claim full listening, native application playback or phone playback only when performed.

Fix only affected source/cues, preserve superseded work privately, and rerun affected checks. Reuse unchanged chapter renders and narration hashes. A final remux still needs final-file checks; a recompressed delivery copy needs codec/duration/audio and representative readability checks.

Check a provider's upload limits before delivery. Preserve the master and create a smaller derivative if needed. A limit encountered on one connector is not a universal provider limit. Recheck the derivative, upload only to the authorised destination, and read back file ID, type, size and privacy; compare a remote checksum when available. Upload success does not establish remote processing or phone playback.

Deliver a usable link/file, duration, a concise scope note, transcript if useful, and the private QA manifest. Stop only services started for this production after final capture/verification, recording their ownership first. Do not terminate unrelated runtimes.
